# Celestial Cookie Consent

Плагин для WordPress, который показывает баннер cookies и сохраняет выбор посетителя на 180 дней. Посетитель может принять или отклонить необязательные cookies и изменить выбор через ссылку `#cookie-preferences`. Добавьте её, например, в футер или на страницу политики cookies. Ссылка открывает окно настроек на любой странице, где плагин выводит баннер, в том числе после сохранения выбора.

В разделе **Настройки → Cookie Consent** администратор может изменить текст баннера. Страница написана на React с компонентами WordPress, а текст баннера читается и сохраняется через `useSettings` и `@wordpress/api-fetch` в стандартном REST API настроек WordPress. Подход описан в [статье WordPress Developer Blog](https://developer.wordpress.org/news/2024/03/how-to-use-wordpress-react-components-for-plugin-pages/). На публичных страницах работает отдельный скрипт на JavaScript.

В разделе **Optional scripts** можно добавить любое число записей. Укажите название, описание и JavaScript без HTML-тегов `<script>`, затем нажмите **Save scripts**. Форма отправляет список через `admin-post.php`, а WordPress сохраняет его в опции `celestial_cookie_consent_scripts`. Редактирование кода доступно пользователям с правами `manage_options` и `unfiltered_html`. Добавляйте только проверенный код. Он передаётся браузеру как данные и после согласия выполняется от имени сайта, поэтому в него нельзя помещать секреты. Сам плагин не отправляет данные на внешние сервисы. Вставленный код может обращаться к ним после согласия.

Названия и описания отображаются в разделе **Customize** в баннере. Посетитель может разрешить все скрипты, отклонить все или выбрать отдельные записи. При первом открытии настройки выключены. При изменении списка плагин запрашивает согласие заново. Если посетитель отзывает согласие после запуска скриптов, страница перезагружается без их запуска. Cookies, уже созданные сторонними скриптами, могут остаться в браузере.

## Установка

Версия 1.0.1 требует WordPress 6.5 и PHP 7.4 или новее. При установке из исходников выполните `npm ci` и `npm run build`. Поместите папку плагина вместе с каталогом `build/` в `wp-content/plugins/`, активируйте плагин. Баннер появится автоматически на публичных страницах.

Список изменений по версиям ведётся в [CHANGELOG.md](CHANGELOG.md).

## Публикация ZIP на GitHub

Обновите версии в заголовке плагина, `package.json` и `package-lock.json`, добавьте соответствующую запись в CHANGELOG и отправьте коммит на GitHub. Затем поставьте тег на этот коммит и отправьте его. Например, для версии 1.0.1:

```sh
git tag v1.0.1
git push origin v1.0.1
```

GitHub Actions соберёт плагин и добавит `celestial-cookie-consent-1.0.1.zip` в **Assets** релиза. Этот ZIP можно загрузить через **Плагины → Добавить плагин → Загрузить плагин**.

Чтобы собрать ZIP локально, выполните `npm ci`, затем `bash scripts/package-release.sh v1.0.1 /tmp/celestial-cookie-consent-release`.

## Обновления через WordPress

Плагин требует PHP 7.4 или новее. После установки версии с механизмом обновления WordPress проверяет последний стабильный публичный GitHub Release репозитория `valeravilks/celestial-cookie-consent`. В разделе **Плагины** появится стандартная ссылка **Обновить сейчас**, если версия релиза новее установленной. Проверку можно запустить через **Консоль → Обновления → Проверить снова**.

Для выпуска обновления синхронизируйте версии и CHANGELOG и опубликуйте тег по инструкции выше. Релиз должен содержать собранный asset `celestial-cookie-consent-VERSION.zip`; автоматические архивы исходников GitHub не используются. Черновики, предварительные релизы, неверные теги и релизы без нужного ZIP пропускаются. При недоступности GitHub плагин продолжает работать, проверку можно повторить позже. Репозиторий и ZIP должны быть доступны без авторизации.

Это добавляет исходящий серверный запрос к GitHub API при штатной проверке обновлений WordPress и загрузку ZIP при обновлении. Посетительский баннер таких запросов не делает. Установка выполняется стандартным механизмом WordPress с его проверками прав и nonce; опции плагина не удаляются. Автоматическая установка обновлений принудительно не включается.

Старую версию 1.0.0 без этого механизма нужно один раз обновить загрузкой нового ZIP вручную. Следующие релизы будут доступны через кнопку WordPress. В локальном wp-env плагин подключён из рабочей папки: проверяйте фактическую замену файлов только на отдельной установке из ZIP, чтобы WordPress не перезаписал исходники проекта.

## Локальный запуск

Запустите Docker и выполните:

```sh
npm ci
npm run build
npm run env -- start
```

Откройте [сайт](http://localhost:8888/) или [страницу настроек](http://localhost:8888/wp-admin/options-general.php?page=celestial-cookie-consent). Данные входа для локального окружения: `admin` / `password`.

Остановить окружение можно командой `npm run env -- stop`. После изменения интерфейса настроек повторите `npm run build`.

Правила разработки описаны в [AGENTS.md](AGENTS.md).

Для повторной проверки откройте публичную страницу с параметром `?debug` и нажмите **Reset consent**. Плагин удалит свою cookie согласия и перезагрузит страницу.


## Языки

Встроенные строки баннера используют язык сайта (**Настройки → Общие → Язык сайта**). Страница настроек использует язык профиля администратора, если он задан. В комплекте английский и русский интерфейсы. Введённый текст баннера, названия и описания скриптов сохраняются в исходном виде.

Русский каталог находится в `languages/`. После изменения PO обновите MO командой `msgfmt --check -o languages/celestial-cookie-consent-ru_RU.mo languages/celestial-cookie-consent-ru_RU.po`. Переводы React также хранятся в JSON в той же папке.

## Блок Gutenberg

Плагин автоматически выводит динамический блок **Cookie Consent** через `do_blocks()` в стандартном хуке `wp_footer`. По умолчанию баннер расположен слева. Ранее добавленный в шаблон или на страницу блок сохраняет выбранное положение, если WordPress выводит его до автоматической вставки. На странице отображается один баннер.

WordPress формирует разметку из `src/block/banner/render.php`. Актуальные настройки сайта и переводы передаются через `wp_interactivity_state()`, а действия посетителя обрабатывает `view.js`. Для блока нужен WordPress 6.5 или новее.

Для выпуска используйте `npm run build`. Для разработки запустите `npm run start:block` и `npm run start:backend` в отдельных терминалах или запустите только ту часть, которую меняете. Обе части используют стандартный `wp-scripts`. Блок обнаруживается по `block.json`, а для админки используется `src/backend/index.js`. Исходники блока лежат в `src/block/banner/` и собираются в `build/block/banner/`. React-админка лежит в `src/backend/` и собирается в `build/backend/`.

## Оформление через theme.json

Шрифты и обычный и контурный варианты кнопок наследуются от темы. Для фона и текста карточки используются цвета темы `base` и `contrast`, если они определены. Иначе используются системные цвета браузера. Слой стилей по умолчанию задаёт рамку, тень, отступы карточки и типографику текста и заголовков. Тема и настройки редактора сайта могут их переопределить. Размер шрифта, отступы и цвета кнопок берутся из стилей активной темы. CSS блока задаёт базовое размещение: карточка внизу экрана подстраивается под ширину ряда кнопок, текст переносится внутри неё, а на узком экране кнопки переходят на следующую строку, диалог прокручивается, а название скрипта и переключатель стоят в одной строке. Переключатели остаются нативными элементами формы.

Чтобы переопределить дефолты, перенесите раздел `styles.blocks["celestial-cookie-consent/banner"]` из [theme.example.json](theme.example.json) в `theme.json` активной или дочерней темы. Файл примера служит справочником. После изменения настроек темы обновите страницу. Пересборка плагина не нужна:

- `typography` задаёт стиль обычного текста, `elements.h2` — заголовка баннера, `elements.h3` — заголовка окна настроек. Описания скриптов и статус обязательных cookies используют 87,5% базового размера. Добавляйте `elements.button`, только если хотите отдельно изменить кнопки баннера в теме.
- `color`, `border`, `shadow` и `spacing.padding` оформляют карточку и диалог через стандартные селекторы блока. На карточке «Настроить» использует контурный вариант кнопки темы, а «Отклонить все» и «Принять все» — обычный. Имена скриптов и описания выводятся обычным текстом, а переключатели используют нативные поля формы.
- Цвет включённого переключателя задаётся в `css` блока через `--ccc-switch-accent`, например `"--ccc-switch-accent: #1764d8;"`. По умолчанию используется цвет темы `contrast`, а при его отсутствии — системный акцент.
- Если нужно изменить свойство, для которого в WordPress нет отдельного поля (например, цвет затемнения), добавьте правило в `css` этого блока.

Дефолтные настройки карточки применяются без отдельной конфигурации. WordPress объединяет их со стилями темы и отдаёт приоритет настройкам редактора сайта, если они заданы. Текст баннера по-прежнему меняется на странице настроек плагина.
